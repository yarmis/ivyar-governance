Master Key Governance Policy

Critical infrastructure key management, custody, and recovery procedures for IVYAR platform

1 Policy Purpose

This policy governs the creation, storage, access, rotation, and recovery of master cryptographic keys that protect IVYAR's critical infrastructure. Master keys represent the root of trust for all system encryption and must be protected with the highest security measures.

2 Key Types & Classification

🔐

Root Master Key

Encrypts all other keys. Split custody. Never stored digitally in complete form.

🗝️

Data Encryption Key

Encrypts data at rest. Derived from master key. Rotated quarterly.

🔑

Service Keys

API authentication, inter-service communication. Rotated monthly.

3 Key Custody Model

🔒 Split Knowledge / Dual Control

The Root Master Key is split into 5 shares using Shamir's Secret Sharing. A minimum of 3 shares are required to reconstruct the key. Each share is held by a different Key Custodian in geographically separate locations.

Key Custodian Requirements

  • Senior leadership or designated security personnel only
  • Background check and security clearance verified
  • Signed Key Custodian Agreement
  • Annual key custody training completed
  • No two custodians in same geographic location
  • Hardware security module (HSM) for share storage

4 Key Generation

1

Ceremony

Air-gapped system, witnessed

2

Generation

FIPS 140-2 compliant HSM

3

Splitting

Shamir 5-of-3 scheme

4

Distribution

Secure courier, verified receipt

  • Key generation performed in secure facility with no network connectivity
  • Minimum 3 witnesses required from different departments
  • Video recording of entire ceremony (stored offline)
  • All materials destroyed after share distribution confirmed

5 Key Storage

Physical Storage Requirements

  • FIPS 140-2 Level 3 certified Hardware Security Module
  • Secure facility with 24/7 monitoring
  • Biometric + PIN access control
  • Fire-resistant and tamper-evident containers
  • Geographic distribution (minimum 3 locations)

Backup Key Shares

  • Encrypted backup of each share in separate secure vault
  • Bank safety deposit boxes in different jurisdictions
  • Annual verification of backup integrity
  • Documented chain of custody for all movements

6 Key Access & Reconstruction

Master key reconstruction is only permitted for:

  • Disaster recovery requiring full system restoration
  • Annual key verification ceremony
  • Scheduled key rotation
  • Legal or regulatory requirement with documented order

⚠️ Reconstruction Protocol

  • Board-level approval required (minimum 2 executives)
  • Security Owner authorization and presence
  • 3 of 5 custodians physically present with shares
  • Air-gapped reconstruction environment
  • Full video documentation of ceremony
  • Key destroyed immediately after use (re-split if needed)

7 Key Rotation

Rotation Schedule

  • Root Master Key: Every 2 years or upon custodian change
  • Data Encryption Keys: Quarterly
  • Service Keys: Monthly
  • Emergency Rotation: Immediately upon suspected compromise

8 Custodian Changes

  • Outgoing custodian's share must be revoked within 24 hours
  • New share generated and distributed to replacement custodian
  • Full key reconstruction and re-splitting if more than 2 custodians change
  • Security audit of outgoing custodian's access history
  • Update of all key custody documentation

9 Audit & Compliance

  • Annual third-party audit of key management practices
  • Quarterly internal review of key access logs
  • Annual key custody verification ceremony
  • Compliance with NIST SP 800-57 key management guidelines
  • ISO 27001 Annex A.10 cryptographic controls alignment

10 Emergency Procedures

In case of suspected key compromise:

  • Immediate notification to Security Owner and all custodians
  • Emergency key rotation initiated within 4 hours
  • Forensic investigation of potential breach
  • Notification to affected parties as required
  • Post-incident review and policy update
